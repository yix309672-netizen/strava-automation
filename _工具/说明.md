# 工具目录说明

项目根目录只留**流程和运行时**必需的脚本，其余都归类到这里。

## 根目录留下的 3 个（别挪走）

| 文件 | 为什么必须在根目录 |
|---|---|
| `_launch_gui.py` | **运行时依赖**：`启动_ADS界面.bat` / `启动_比特界面.bat` 会调它。挪走启动器就废了。 |
| `_同步分发.py` | 把 `主脚本/`、`界面/` 的改动同步进 `_分发给同事/`，并跑质检门（标记缺失 / 读写不一致 / bat 合规）。 |
| `_打包给同事.py` | 出同事包。**现在只产出一份**：`桌面\Strava发布包\发给同事_脚本包_最新.zip` |

## 三层分类

### `生成\`  —— 改文案、改启动器时才跑
| 文件 | 产出什么 |
|---|---|
| `_生成_中文提示.py` | `_分发给同事\msg_*.txt`（15 个中文提示文件） |
| `_生成_中文启动器.py` | `_分发给同事\*.bat`（6 个启动器，纯 ASCII + CRLF） |
| `_生成_隐藏支持.py` | `_hide.ps1`（藏黑窗口）、`_msgbox.vbs`（弹中文提示框） |
| `_生成_界面启动器.py` | `启动_ADS界面.bat` / `启动_比特界面.bat`（独立窗口，不会连坐） |
| `_生成_推送启动器.py` | `桌面\推送更新.bat` + `项目\_发布工具\` 的备份 |
| `_生成_活动轨迹.py` | **一批活动轨迹（TCX）**，给新号上传用。★ **踩真实路网**（问 OSRM 要环线），所以几何必定在陆地上、形状就是街道本身；生成后还会自查一遍水，踩到就换锚点重来。默认出四套（芝加哥/洛杉矶 × 跑步/骑行）各 60 条到 `桌面\运动轨迹\`。用 TCX 而非 GPX 是因为 `Sport="Running"/"Biking"` 能让 Strava 自动认成 Run/Ride。**要联网**，缓存在 `_过程记录\_路线缓存.json`，重跑不再请求 |
| `_修_素材跑水里.py` | 把素材里**跑到水里**的 GPX 换成新造的（走真实路网）。文件名/日期/格式/距离都尽量对齐原来那份，起始时间统一挪到早上。**默认只看不改**，`--apply` 才写，原件先备份到 `项目\_备份\_替换水里跑的_<时间>\` |

| `_验证_服务器包带修复.py` | 把服务器上的包**拉下来解开**逐条核验 |
| `_验证_列序错位.py` | 表格列序：取值各归各位 + 源码里没有写死的数字下标 |
| `_验证_采集计数.py` | 界面「本次 N/M · 今日 T」+ 跨零点翻页 + 实时刷新 |
| `_验证_关闭多余标签.py` | 多余的浏览器标签自动关闭，且不误关工作页/内部页 |
| `_验证_链接实时落盘.py` | 两份文档都是写一条立刻有一条，且不重复、不双写 |
| `_验证_链接跨零点.py` | 任务跑过 00:00 会切到新一天的文件 |
| `_验证_快速编辑已关闭.py` | 关掉控制台快速编辑（不然点一下黑窗口程序就停） |
| `_验证_界面消息落盘.py` | 界面自己的消息会写进 `logs\run_*.log`（以前一个字都不落盘） |
| `_查_结果文件错位.py` / `_查_账号文件错位.py` | 数据有没有被写坏 |
| `_查_错位诊断.py` | 错了几格、能不能还原 |
| `_验证_错位还原假设.py` | 还原前先验假设成不成立（**改数据前必须跑**） |
| `_修_结果错位.py` | 把坏掉的数据还原回去。**默认只看不改**，加 `--apply` 才写，且自动备份 |
| `_修_密码丢失.py` | **密码专用**：错位时 password 被 login 覆盖成 `是/否`，从历史快照/备注里按邮箱捞回真密码。默认只看，`--apply` 才写 |
| `_验证_密码对底稿.py` | 拿桌面上的账号底稿（`运动真号邮箱.txt` 等）核对全库密码 —— 这是唯一权威标准答案，能揪出 `kaOS99kY`/`ka0S99kY`（字母O/数字0）这类肉眼看不出的错别字 |
| `_验证_密码自愈.py` | 界面的密码列自愈：错位后按邮箱找回、查不到要清空、刷新要顶掉坏值、保存时坏值不得覆盖账号文件。**源码 + 分发包里的界面一起测** |
| `_验证_上传标题.py` | 上传的活动标题/类型：**跟着素材走** —— 骑行 TCX(`Sport="Biking"`) → `Morning Ride`/`Ride`，跑步 → `Morning Run`/`Run`，认不出退回跑步。每个文件卡片都填上。**标题在卡片上写死，不是改素材文件** —— Strava 自动起的名按【账号时区】算，同一份素材在不同号上不一样。含"解析没完成时表单不可见"的等待逻辑 |
| `_验证_上传标题_真机.py` | 同上，但**打真实 Strava 上传页**跑一遍（调引擎自己的函数、读回页面上的值、不点保存）。返回 3 = 号被 Strava 限流，验不了，不是产品问题 |
| `_验证_生成的轨迹.py` | 检查生成的 TCX：合法、`Sport` 对得上、本地早上开始、首尾闭合、点与**线段中点**都不在水里（内置一条芝加哥湖岸线；只看点会漏掉"两点之间跨水"）、点数/间距像真人。顺带体检原来的素材 |
| `_验证_采集已分离.py` | **「开始任务」里不许有采集**：`run_one` 里没有 `collect_regions`/`make_claim_client`、但会员状态和真实姓名还在读；`collect_one` 里采集调用还在；`pending_todo` 不再塞"采集" |
| `_验证_近期活动筛选.py` | **只采近期还有活动的人**：拿假页面把 `check_athlete` 真跑一遍，验 3/59/61/90 天的边界、读不到日期时的 4 周兜底、`recent_days=0` 关闭、以及粉丝超标照样淘汰 |
| `_验证_近期活动_真机.py` | 同上，但**打真实资料页**（比特派窗口，只读）：验页面上真读得到 `<time datetime>`、判定对不对得上。`python _验证_近期活动_真机.py 7` 可临时收窗口，用来看"淘汰"那一半 |
| `_清上传记录.py` | 清掉「已上传过」的记账，让轨迹能重传（改标题这种要返工的场合）。默认只看，`--win _2,_15` 或 `--all` 才写。**必须先去 Strava 删掉老活动**，否则引擎看到活动数>0 会跳过上传 |
| `_试跑_真机.py` | 真引擎 + 真窗口 + 真服务器跑一次采集（`python _试跑_真机.py <号> <目标人数>`） |
| `_试跑_塞标签.py` | 往窗口里故意塞几个标签，用来验证自动清理 |
| `_试跑_探API.py` | 看指纹浏览器 API 通不通、有哪些可用窗口 |
| `_跑批_ADS编号段.py` | **按编号段跑一整批**（`--from 83 --to 104`），走的是界面「▶ 开始任务」同一条路（`run_one_seq`），**一个链接都不采**。`--dry` 只看计划、`--jobs N` 改并发、`--keep` 不关浏览器。重复邮箱的号会自动排到最后（免得并发时两个浏览器登同一个 Strava 号） |
| `_验证_骑行类型可选.py` | **真机**：开一个已登录的号，投喂 1 个骑行 TCX，把上传页运动类型下拉框里的 53 个 `data-value` 全打出来，确认引擎要用的 `Ride` 在不在。**只解析不保存**，零活动产生 |
| `_验证_上传结果.py` | **真机只读**：读某个号上传上去的活动标题和类型（训练日志页），核对是不是全成了 `Morning Ride` / `Morning Run` |
| `_查_设置页为什么不可见.py` | 设置页五步全报"元素不可见"时用它：打出真实 URL、弹窗、按钮、`editable-setting` 行数。2026-09-24 就是靠它查出**真因是 `/settings/profile` 被重定向回 `/onboarding/continue`**（onboarding 弹窗没填） |
| `_修_位置写错了.py` | 引擎记的 location 是【它想写的值】不是 Strava 真存下的值 —— 写错了也不会被发现，`pending_todo` 永远认为已完成。这个工具把指定号的状态记录清掉，让下一轮重做「位置」。默认只看，`--win 84,85 --apply` 才写 |
| `_验证_按号采集地区.py` | **按号采集地区/年龄**：两个界面都有 region/age 两列且**不在** `PROFILE_COLS` 里（在里面刷新就会把用户设的值冲掉）、按号设置是**主线程**读的（子线程读 tree 会死锁）、留空不动 cfg、两个引擎的 `_daily_path` 传 region 就是 `地区_日期.txt`。注释和 docstring 都剥掉再查 |
| `_验证_按号采集地区_真机.py` | 同上但**真把界面建起来跑**：建 13 列表格、`_fill` 两行（一行设地区一行留空）、复刻 `_start` 的 rowset 收集和 `_work` 的 cfg 覆盖，断言"设了的被覆盖、留空的原封不动" |
| `_验证_版本号.py` | **版本号全链路**：真源 `主脚本/app_version.py` → 两个引擎 import 得到（断了会**静默**兜底成 `v?`）→ 界面标题栏真显示（真建窗口读 `title()`）→ `_同步分发.py` 的 PAIRS 有它 → `_打包给同事.py` 的 NEED 有它 → 分发包里值一致 → 桌面推送脚本也登记了。**任何一环断了都不报错，只会静默退化**，所以专门验 |

### `历史\`  —— 一次性脚本，归档备查
已经完成使命的 `_验收_*` / `_查_*` / `_修_*` 等，**一个都没删**。
哪天想翻"当时为什么这么改"，还能在里头找到依据。

## 注意

- 这些脚本用 `_find_project_root()` **向上找项目根**（判据：有 `主脚本/strava_ads.py` 的那一层），
  所以放在哪一层都能跑，不用改路径。
- `历史\` 里的老脚本**没有**做这个适配（它们按原来的位置写死了路径），
  真要重跑，可能需要先看一眼里面的 `ROOT` 是怎么算的。
