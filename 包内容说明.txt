  去重服务（本项目最关键的部分）
════════════════════════════════════════════════════════

  claim_server.py   部署在 VPS 上的中心服务（FastAPI）
  claim_store.py    SQLite 存储层（WAL + 原子写入）
  claim_client.py   客户端（脚本自动调用）
  deploy_vps.py     一键部署脚本（含 SSH 端口自动探测）
  geo_cities.py     17087 个美国城市坐标，用于位置带筛选
  管理员手册.md      服务端运维手册

  服务地址写在 配置/config.json 的 claim_server / claim_key。
  20 个人同时跑时，由中心服务保证【不会采到同一个运动员】。
  连不上服务时会【拒绝采集】—— 这是故意的，防止退化成本地去重
  导致 20 个人重复采同一批人。

════════════════════════════════════════════════════════
  依赖说明
════════════════════════════════════════════════════════

  运行时要 4 个包 + tkinter: playwright / requests / numpy / pillow

  ★★ 必须用官方【完整版】Python，不能用 embeddable（便携版）★★

     界面是 tkinter 写的，而 embeddable 包里根本没有 tkinter
     （整个 zip 只有 34 个文件，没有 _tkinter.pyd / tcl / tkinter 包）。
     用它的话界面 100% 打不开：
         ModuleNotFoundError: No module named 'tkinter'

     ★ 这个坑真实发生过：同事装完显示 "Environment is READY"，
       然后双击界面毫无反应。已修复 —— 启动.bat 现在用完整版安装器：
         python-3.11.9-amd64.exe /quiet InstallAllUsers=0
             TargetDir=<包内 _python> Include_tcltk=1 Include_pip=1
             Include_launcher=0 PrependPath=0 AssociateFiles=0 ...
       InstallAllUsers=0 → 不需要管理员，也不碰系统 PATH / 文件关联。

     ★ tkinter 不能 pip 安装，所以启动.bat 会单独检查它。

     ★ 安装器按产品名去重：如果这台机器已经装过 Python 3.11（比如
       之前跑过旧包），它会去"修复"那一个而不是往我们目录里装。
       启动.bat 有降级逻辑处理这种情况：复用已有的那个，并把路径
       写进 python_path.txt 供 Start_*.bat 使用。

  ★ 不需要 DrissionPage（脚本全程没引用过）
  ★ 不需要浏览器内核（脚本用 CDP 连接指纹浏览器已开好的浏览器，
    全库零处 .launch() 调用，所以不用跑 playwright install chromium，
    省掉约 196 MB 下载）

  ★★ 发布新版本（同事自动更新，不用重发包）
════════════════════════════════════════════════════════

  改完东西后，两步：

      python _重做启动器.py      # 重新生成分发包 + 发货前体检
      python 发布更新.py          # 上传到 VPS，同事下次开界面自动更新

  发布完你会看到版本号（如 27af4219580976ac）。

  ★ 同事那边什么都不用做 —— 双击 Start_*.bat 时会自动：
       比对版本 → 有新版就下载替换 → 没新版就静默跳过
    只换脚本，账号 / 采集成果 / 进度 / 去重记录 / Python 环境
    一律不碰；config.json 只补【新增的键】，填过的值不覆盖。

  ★ 服务器连不上时自动跳过，不影响同事使用。

  ★ 想先本地体检不上传:  python 发布更新.py --dry-run

  发版端点（这次新加的）:
    GET  /pkg/manifest      版本 + 每个文件的 sha256
    GET  /pkg/latest.zip    整包下载
    POST /pkg/upload        管理员发版（发布更新.py 调用）

  服务端文件在 VPS 的 /opt/strava/，服务名 strava-claim。
  要改服务端: python 部署更新端点.py （会问密码，自动备份+上传+
  语法自检+重启+验证；语法不过会自动回滚）


════════════════════════════════════════════════════════
  ★ 每次发货前必做：重新生成分发包
════════════════════════════════════════════════════════

      python _重做启动器.py

  它会做两件事：
    1. 重新生成启动器（启动.bat / Start_*.bat / 更新.bat /
       Test_Server.bat / open_app.py / 使用说明.txt），
       并把 主脚本/ 的两个引擎、claim_client.py、update.py
       同步进分发包（以前靠手工复制，跑偏过一次）
    2. 「发货前体检」——扫描整个分发包，只要发现任何一个真实邮箱，
       就【拒绝打包】并删掉旧的 zip。

  ★ 这一步很重要。曾经出过事：有人直接从 _分发给同事/ 里打开了
    界面，界面把真实账号写进了 ads_results.json，差一点连账号一起
    发出去。现在有了体检，这种情况会被直接拦住。

  ★ 平时不要直接在 _分发给同事/ 里面双击运行界面。
    要测试请先复制一份到别处再测（界面会往运行目录写结果文件，
    而且它的 _find() 会去上级目录的 配置/ 和 数据/ 找文件）。

  其它工具:
    _测界面.py   ★ 改动启动器后务必跑一遍（约 3 分钟）

      它模拟两种同事环境，并且【真的把界面跑起来】：
        场景 A  全新机器（没有 Python）→ 完整安装 → 启动界面
        场景 B  旧版残缺 _python（无 tkinter）→ 应自动替换
      每个场景都验证：import tkinter、真建一个 Tk 窗口、4 个依赖、
      界面进程存活 20 秒、Start_BitBrowser.bat 能拉起界面。

      ★ 为什么必须跑它：tkinter 那个 bug 就是"只查语法、不跑界面"
        漏掉的 —— ast.parse 能过，import playwright 也能过，
        界面照样 100% 打不开，同事那边表现为"双击毫无反应"。

    _测真机更新.py   对着真实 VPS 验证自动更新（约 1 分钟）

      模拟一个"旧版 + 有本地数据"的同事端，跑一次 update.py，
      验证脚本被更新、config 缺的键补回、而【账号和采集成果
      一个字节都没动】。改动 update.py 或服务端后跑一遍。
